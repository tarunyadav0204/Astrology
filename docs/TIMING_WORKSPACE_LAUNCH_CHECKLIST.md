# Timing Workspace — astrologer launch checklist

This is the delivery checklist for the Charts & Dashas **Timing** workspace.
Every item changes a live calculation, an auditable result, or the practitioner
workflow. The screen must not manufacture a date or a promise from a visual
placeholder.

## P0 — prediction contract

- [x] Make the D1 natal-event promise a first-class result and show it before any timing verdict.
- [x] Describe exact contacts as **transit triggers**, never as confirmation that the event will occur.
- [x] Give each result a precision grade: broad period, narrowed period, or date-level trigger; never imply time-of-day precision without a location-aware muhurta calculation.
- [x] Show counter-evidence and missing confirmations alongside supportive evidence.
- [x] Keep the Dasha, varga, and transit evidence independently auditable for every selected window.

## P1 — event and practitioner controls

- [ ] Replace broad life-area buttons with event stages whose house/varga rules are distinct and documented.
- [x] Support a custom start/end date horizon, plus historical validation, rather than only a calendar year.
- [x] Expose every relevant varga equally; D7 must not receive a higher evidence standard than D2/D4/D9/D10/D24/D30.
- [ ] Offer finer Dasha layers only when their calculator and an independent trigger can justify the requested precision.
- [x] Display calculation profile, ayanamsha, node setting, birth-chart timezone, and the event-location/timezone requirement for muhurta.

## P2 — calibration and launch assurance

- [ ] Let practitioners record occurred, delayed, and did-not-occur outcomes against a saved forecast without rewriting the original forecast.
- [ ] Add regression tests for all event contracts, precision grades, counter-evidence, historical ranges, and unsupported precision.
- [ ] Run backend tests, frontend production build, lint/type checks available in this repository, and a visual review of the Timing workspace.
